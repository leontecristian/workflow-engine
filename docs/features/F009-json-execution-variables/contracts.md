# F009 concrete contracts — revision 3

This technical annex is normative for [specification revision 3](spec.md), completing G01–G04 within D01–D17. It specifies future behavior, not implemented or verified behavior. The four process documents remain spec, plan, tasks and implementation.

## C01 — Java values and integration

Under `io.github.leontecristian.workflow.core.dto.runtime`, replace ScalarLiteral with sealed WorkflowLiteral, permitting the existing TextLiteral, BooleanLiteral and NullLiteral and a new final WorkflowJsonValue. Replace ScalarValue with `WorkflowValue(VariableValueType type, WorkflowLiteral value)`. Keep the six scalar validation/normalization rules; JSON accepts only WorkflowJsonValue or NullLiteral. Java null is never a value token. All carriers and returned maps are immutable.

WorkflowJsonValue exposes `static WorkflowJsonValue parse(String json)` and `String toJson()`. Its factory is the core-owned codec entry point: accept exactly one non-null object/array, validate generic limits and store a canonical immutable snapshot. Top-level `null` is represented by `new WorkflowValue(JSON, NullLiteral.INSTANCE)`, not a nullable wrapper. Parsing errors use WorkflowExecutionException INVALID_INPUT; resource excess uses LIMIT_EXCEEDED. No Jackson type, DTO serializer or mutable tree getter is public. A private package helper in dto.runtime performs parsing/canonical serialization; expression views remain in service.expression. Tree retention is optional; semantic behavior must not depend on caching.

StartInputs becomes `StartInputs(Map<String, WorkflowLiteral> values)`, retaining empty(), defensive copies, absent-key semantics and the 100-key bound. Raw text tokens retain their spelling until definition-directed validation; this is necessary for replay before defaults/state-dependent execution. WorkflowValue represents a validated typed value; WorkflowLiteral represents a supplied token. These are distinct stages of one value model, not competing JSON APIs.

ServiceActionResult becomes `ServiceActionResult(Map<String, WorkflowValue> outputs)`. WorkflowServiceAction.execute receives `Map<String, WorkflowValue>`. ActionField accepts JSON with existing required/nullable rules. WorkflowVariableView retains key/type/initialized and changes value to WorkflowValue; value is Java null only for an uninitialized view. Initialized explicit null has a typed NullLiteral. Start/replay signatures keep StartInputs; result/receipt summaries and completion commands gain no variable payload. Update all callers together; remove scalar-only carriers and unnecessary compatibility overloads.

## C02 — Exact codec and identity

Use one private strict Jackson parser: duplicate detection, one document only, valid Unicode, bounded input/depth/count/string/number tokens, no polymorphic typing or arbitrary Java object conversion. Parse every nested numeric token directly as BigDecimal, including integer tokens. Construct decimal tree nodes without trailing-zero stripping. Never pass through float/double or a scale-stripping canonicalizer.

Here, numeric projection and depth/count rules apply to execution JSON values, including definition defaults/literals, not indiscriminately to the enclosing definition or protocol fields. Keep structural fields such as schemaVersion as integer tokens accepted by the existing document validator. Use shared codec logic with boundary-specific limits, not one global 256 KiB/depth-16 parser profile: a definition, start request, service map and history envelope each has its own D15 allowance. Count depth 16 from each execution value's root container, excluding its envelope. Retain 100 properties per object, 1,000 items per array, 16,000 code points per JSON string, 256 per property name and 128 per numeric token. All container elements count, including nulls.

WorkflowJsonValue.parse bounds raw input to 2 MiB UTF-8 before tree construction, then enforces the 256 KiB UTF-16 canonical value limit. Streaming host ingress separately counts the complete raw request. Standalone factory whitespace is bounded but does not count toward canonical value size. Definition uploads retain their separate upload bound. Serialization must stop on budget exhaustion rather than allocate an arbitrarily large string and check afterward. RuntimeJson's existing 128 KiB tree/evidence helpers must be separated by purpose: receipt limits cannot accidentally cap valid history or execution data.

Canonical JSON has no whitespace, recursively sorts object keys by Unicode code point, retains array order, escapes quote/backslash and control characters (lowercase four-digit Unicode escapes for controls), and emits other valid Unicode literally. Emit numbers using BigDecimal.toString(), retaining unscaled value and scale. Negative zero loses its sign because BigDecimal does not retain it. This is not source-text preservation: `1e2` and `1E+2` share identity; `100` and `1E+2` differ in scale. Required vectors include `1` versus `1.00`, `0.00`, `1E+2`, `1E-10`, nested reordered objects, null and absent keys.

Check DECIMAL(38,10) representability without rounding or expanding a huge exponent. A temporary normalized value may be used for capacity checks, never for stored/exported identity. Reject out-of-capacity values, BigDecimal scale overflow and tokens exceeding existing bounds. Account for canonical output limits as well as input limits. Expression intermediates retain F008 numeric/work limits; accepting a stored number does not waive those limits when arithmetic is evaluated.

Use `wf-json-c14n-v2` for scale-preserving definition/value canonicalization, `wf-json-variable-validator-v1` for the new definition validator and `wf-runtime-request-v3` for all new runtime command fingerprints. Keep definition schemaVersion 1 and D01 binding notation. Definitions, including defaults/literals, must use the scale-preserving codec before hashing/storing; replacing runtime serialization alone is insufficient. Unknown schema configuration fails publication explicitly. Validation-context hashing still includes referenced action descriptors and schema digest.

Fingerprint SHA-256 over UTF-8 canonical `{version,operation,actorKind,actorRef,request}`. Retain existing command-specific request fields and exact identifier strings; start always includes an inputs object, even when empty. Include full supplied values before defaults and normalization; retain omission versus explicit null and supplied scalar text spelling. Exclude commandId (receipt key), occurredAt and correlationId as today. Preserve hostStartIntent. Use resultSchemaVersion 3 with the existing WorkflowExecutionResult field shape and variable-length history ranges for all new receipts; no dispatch to old readers. Successful authorized replay precedes definition-default application, service invocation or expression evaluation.

## C03 — Expression integration

Extend F008 inspected/rebuilt AST nodes, not reflective application-object access. Parse standard SpEL navigation and retain its ordering/short circuit semantics; use custom read-only nodes for JSON access and container equality. Publication still checks declared variable roots; computed keys/indexes apply inside the selected JSON variable. Do not expose bare #vars as an application object. Keep all existing prohibited AST forms prohibited.

Object dot/bracket reads use exact case-sensitive keys. Array brackets require a finite numeric whole number, without coercing text/null/Boolean or truncating fractions. Test range before converting to a bounded Java index: every negative or too-large whole number returns null. Keys containing dots/brackets are single keys; use standard quoted bracket literals and SpEL escaping. A string or number is not a navigable JSON container.

Validate finiteness and integrality before the range test: -1.5 is an error, not an out-of-range null. Handle zero without expanding its scale. Use bounded magnitude/scale checks for BigDecimal integrality and only convert an in-range whole value to int. In bracket expressions, evaluate computed operands against the same expression root as SpEL, not against the current JSON object. Property names needing quoting use `['key']`; no implicit host/root property lookup is introduced. Declared variable root selection retains F008's fixed property/string-literal key contract; computed navigation is inside that root.

Ordinary navigation through null fails; explicit null-safe access returns null for that operation. Null-safe indexing skips index evaluation when its receiver is null; subsequent operations in the chain follow their own null-safety marker. Missing properties, explicit null and out-of-range results project to null but retain distinct trace states. Compare actual integration with the pinned Spring parser before accepting AC03/04; an implementation mismatch must be fixed, not documented as a successful verification.

For == and !=, two JSON containers use recursive D13 equality; object versus array is unequal, and container versus null is unequal. Container versus a non-null scalar is an operand error. Ordering/arithmetic on containers fails. Scalar comparisons remain native restricted SpEL. Charge each visited comparison node and string/key work to the same 10,000-work evaluation budget, including computed accesses; check limits before traversal/copying. Do not delegate unbounded JsonNode.equals or serialize entire containers merely to compare them. Never evaluate skipped operands for evidence.

Keep F008 AST/source/operator charges. Additionally charge one unit per resolved navigation segment, one per UTF-16 code unit of an accessed key, one per pair of nodes visited in container comparison and one per UTF-16 code unit examined in compared strings/keys. Numeric-leaf comparisons charge the combined coefficient digit counts before comparing exact value/scale. Stop as soon as inequality is established; never traverse the remainder for evidence. Evidence serialization has its separate bounded byte/count accounting, so copying retained operands does not silently perform an unmetered comparison. Publication allows dynamically typed nested JSON results; validate their actual operand/index types at evaluation instead of requiring a field schema.

## C04 — Evidence and errors

Select inline evidence, with no immutable-reference repository. VARIABLES_WRITTEN retains `{nodeKey,writes}`; each write retains `{variableKey,type,source,previousInitialized,previousValue,value}`. Values use ordinary exact JSON tokens, including complete containers. previousInitialized distinguishes no prior value from explicit null. Preserve existing source binding metadata and sorted destination ordering.

Use history detailsSchemaVersion 2 for all new records. Retain existing event envelope and event-specific fields; replace expression variable-read entries with `{variableKey,path,state,value}`. Path is an ordered array of `{kind:"PROPERTY",key:"..."}` or `{kind:"INDEX",index:"..."}` segments; index is the resolved exact whole-number decimal string. An empty path denotes a whole-variable operand. States are VALUE, NULL, MISSING, OUT_OF_RANGE and NULL_SAFE; value is null for all but VALUE. Capture completed leaf/operand reads rather than intermediate container copies. Computed-key/index reads appear separately in evaluation order. Container operands retain complete values; no references to mutable current state. Keep expression/transition identity and evaluation result in existing routing records.

Retain `type` on each read entry as the declared root variable type (JSON for nested JSON reads), alongside the fields above. Preserve read occurrences in execution order; do not collapse different paths or repeated reads into F008's per-variable map. When null-safe access is skipped, retain the originating NULL/MISSING/OUT_OF_RANGE read and a NULL_SAFE entry at the same reached path, without inventing a resolved skipped segment. For `#vars.booking.absent?.[#vars.index]`, record MISSING at PROPERTY absent and NULL_SAFE there; do not evaluate or record index. For an actual out-of-range index, retain the attempted resolved INDEX segment. The evaluation's expression identity supplies the skipped syntax.

Update all producers and consumers of the new history version together, specifically RuntimeHistoryBatch, RuntimeDefinitionPins, WorkflowExecutionService's created-event recovery, WorkflowRuntimeQueryService's exact task-submission read, and host history rendering. Their existing version-1 checks must accept the new version-2 baseline; no legacy branch is required. New-instance start, subsequent completion, pinned-definition loading, replay and exact task-history retrieval must all work under this same baseline. A version change limited to event writing is incomplete.

Enforce D15 per-record/cumulative limits and response returnability before commit. Evidence overflow is LIMIT_EXCEEDED and rolls back the whole command. Delivery remains metadata-only. Persist no partial failure trace as successful history.

Keep existing sanitized category/HTTP mapping: malformed/duplicate/invalid supplied JSON or type is INVALID_INPUT/400; generic capacity is LIMIT_EXCEEDED/422; uninitialized reads are UNINITIALIZED_VARIABLE/422; bad navigation/operands/non-Boolean conditions are EXPRESSION_EVALUATION_FAILED/422; evaluation work exhaustion is EXPRESSION_LIMIT_EXCEEDED/422. Invalid action result shape/type is INVALID_ACTION_OUTPUT/500, with capacity excess still LIMIT_EXCEEDED. Corrupt persisted values are HOST_CONFIGURATION/500. Existing conflict/auth mappings remain. No payload, evaluated value or internal Jackson exception text in public errors/log messages. Definition errors use existing location-aware validation diagnostics.

These mappings are boundary-specific: exceptions thrown inside a service action before it returns retain the existing SERVICE_ACTION_FAILED contract; returned outputs are then validated as outputs. A codec exception raised while decoding persisted state is mapped to HOST_CONFIGURATION, not reported as a bad caller request. Exclude parser source excerpts and exception causes containing payloads from logging as well as HTTP responses.

## C05 — Persistence and bounded reads

Use existing workflow_variable.json_value; no new value column/table or initialization flag. A declared but uninitialized variable has no row. On first assignment insert a row; subsequent assignments replace its value. An initialized JSON null has a row with value_type JSON and all value columns SQL NULL. Under the early aggregate claim, prepare/validate all mappings and evidence, explicitly replace each entity value and clear other typed columns. Missing optional outputs cause no write. Do not delete a row to represent null or clear initialization. Derive the read projection's initialized flag from row presence and the pinned declaration. Flush/capture the final managed instance version through existing runtime transaction orchestration. No reliance on in-place JsonNode dirty tracking.

Select an additive core changeset file `db/changelog/workflow/changes/003-json-execution.xml`, included after 002, with changeset ID `003-json-history-capacity` and author `workflow`. Replace ck_workflow_history_json with the same ISJSON condition and DATALENGTH <= 4194304, using a checked/trusted constraint. Do not edit applied 001/002 or create old-data conversion tooling. This minimal setup choice does not promise compatibility for old runtime records. No destructive/shrinking rollback is required. Only future authorized implementation creates/runs this file.

Reuse WorkflowRuntimeQueryService variable paging, history summaries and findHistoryEvent. History list remains summaries, with its existing sequence cursor; detail returns `{summary,detailsJson}` with detailsJson as exact JSON text. Measure the complete encoded response, including escaping: detail <=8 MiB UTF-8; variable pages <=1 MiB UTF-8. Reduce page count and return the last included key/sequence cursor; never skip/truncate an item. Reject any new history record whose complete detail response cannot fit before committing it. Apply D15 budgets in their stated encodings, including both old/new inline values.

Preserve variable paging's expectedLockVersion requirement after the first page and its before/after version check. An HTTP variable item remains `{key,type,initialized,value}`: value is the raw object/array for initialized JSON, null for explicit null, and null with initialized false for an uninitialized declaration. Do not serialize WorkflowValue's Java wrapper fields onto the wire or encode its object/array as a string. History detail deliberately retains its existing detailsJson text field; exact decoded text must remain available to the console. Core and host pagination must measure the actual selected wire shape, including envelope/escaping, and return a nonempty page whenever a next item exists and fits.

## C06 — Host and worked integration

Update existing test-host controller.runtime.ConsoleRuntimeController, service.console.ConsoleWire/ConsoleErrors, service.runtime, service.sandbox and related dto.runtime/dto.sandbox carriers. No new endpoint. Start and start/replay accept ordinary object/array input tokens, with 2 MiB UTF-8 streaming ingress bounds.
