The access adapter is request-aware through host injection, but exposes only workflow-owned/standard Java types. Use `requireInstanceRead(long instanceId)`, `requireHistoryRead(long instanceId)` and `readableLinks(long instanceId, Set<ViewerLinkReference> candidates)`. The first operation authenticates and authorizes the instance and is called for every endpoint, including graph; history endpoints additionally call the second. No separate authentication hook, GRAPH grant or permission administration layer is needed. The sandbox maps both read checks to its current instance access policy; another host may deny full history while allowing instance viewing.

Graph reconstruction uses internal core summary reads after the INSTANCE check, not the public history controller or its HISTORY check. It returns only the specified graph projection. Keep adapter failures explicit; never replace a failed authorization operation with permissive data or a cached previous grant.

A link reference carries activity identity and an optional candidate task identity; returned grants identify activity and task access separately and must be a subset of supplied candidates. This operation reuses the host's existing destination access rules. Authentication/denial use documented viewer exceptions, not Spring Security or Keycloak objects in public contracts. Host policy may read through documented core APIs or its own business links; web never depends on host implementation. Correlation metadata is separate from authorization: optional web configuration identifies a trusted request attribute populated by the host; the scoped advice reads its string value or returns null. Do not create another required adapter for this metadata or trust an arbitrary incoming header.

Explicit configuration registers controllers/services/advice only when imported. Controllers must not become active through ordinary component scanning; use import-created beans and test that behavior. Base path is required (sandbox supplies `/console/api`), with validation against empty/root paths or mapping syntax. Only one viewer mount per application is supported in F013. Scope serialization and exception handlers; remove any ambiguity with the sandbox's existing global advice for extracted controllers without changing unrelated error behavior.

The no-activation test must include scanning the web package, not just placing its JAR on the classpath; configuration discovery must not indirectly activate the controllers. Exact registration mechanics remain an engineering choice subject to this test.

Keep graph reconstruction in web as a read projection over `WorkflowRuntimeQueryService` and `WorkflowDefinitionService`, using the host transaction manager and existing read-only transaction semantics. Retain pin/watermark checks, bounds and deterministic layout data; do not introduce graph persistence. Extract minimal read-side exact encoding, not command parsing/body validation. Keep summary-page size calculations identical to the existing codec. For exact events, preserve F009's dual 4 MiB stored-details limits and enforce the 8 MiB UTF-8 envelope limit after final web serialization, testing escaping/Unicode at the boundary. Do not apply the summary-page ceiling to exact events or introduce duplicate DTO mapping where existing detached types suffice.

Sandbox adapter resides in `io.github.leontecristian.workflow.testhost.service.runtime`; explicit activation resides in `io.github.leontecristian.workflow.testhost.configuration.console`. ### Testing the host policy boundary

The sandbox does not recreate APOLO permissions. Its production-style sample adapter delegates INSTANCE and HISTORY checks to the existing administrator/assigned-reviewer policy, including completed assignments, and delegates graph links to existing task/activity access checks. No new roles, permission tables, configuration screens or runtime permission switches are required.

Focused isolated tests supply a small access-adapter double with deterministic allow/deny outcomes to exercise instance allowed/history denied, instance denied, unauthenticated access and independently hidden destination links. These are test fixtures, not configurable end-user permissions. Guarded integration tests exercise the real sandbox adapter against its existing assignments. The minimal NgModule consumer may use denied-read fixtures to verify presentation only; it does not establish backend authorization.

APOLO will later supply an adapter using its trusted identity, business associations and authorization services. Sandbox evidence proves that the library obeys host decisions; it does not prove APOLO policy, tenant isolation or business-link correctness. Those remain actual APOLO integration checks under ASM-01 and C09.

## P03 — Angular library and sandbox composition

R01/06/08; AC01/07–10. Select additional compatible Angular 19 library tooling from published metadata during authorized T04; record exact pins before edits. Reuse the reconciled F012 TypeScript, Node/npm, RxJS and Angular baseline. Use partial library compilation and Angular/Material/CDK peers, with no bootstrap or bundled Zone.js. Avoid speculative management/designer entry points.

Public exports: `WorkflowInstanceViewerComponent`, `WorkflowHistoryComponent`, `WorkflowHistoryEventComponent`, `WorkflowInstanceGraphComponent`, read/message/error types and the `WORKFLOW_VIEWER_READS` and `WORKFLOW_VIEWER_NAVIGATION` injection contracts. Keep internal layout/codec helpers private unless needed by a documented consumer. Read operations mirror the four routes: `instance(id, signal)`, `history(id, afterSequence, limit, signal)`, `historyEvent(id, sequence, signal)` and `graph(id, signal)`, returning typed promises and accepting AbortSignal. Core values never pass through JS Number when their wire contract is string-based.

Define one small normalized read error with the R06 category and optional safe server code/correlation ID. Map aborts to CANCELLED, HTTP 401 to UNAUTHENTICATED, concealed denial/404 to NOT_FOUND, the limit code to LIMIT_EXCEEDED and other transport/protocol/server failures to FAILED. A host that returns 403 for denied reads normalizes it to NOT_FOUND for this UI. Expected cancellations produce no alert; failed reads use viewer wording and manual refresh. Keep this normalization within the read adapter; do not change command/replay error handling.

Data-loading components accept instance identity (plus event sequence where relevant) and a host session-scope input that changes on login/logout/identity replacement; missing active scope clears content and performs no reads. This input is a lifecycle invalidation key, not a permission or credential. Navigation supplies optional URL-tree destinations for instance/history/event/task/activity intents; components must not invent sandbox route names. Graph itself accepts a detached model and resolves navigation intents without fetching. Each component accepts a reactive messages input with English defaults; the host replaces it on locale changes and composed components pass it through. No translation service, notification bus or root registration is needed. Final TypeScript signatures are recorded in public API documentation/tests before implementation of consumers, preserving these requirements.

Use an opaque session generation, including a new generation for same-user re-authentication, and a per-load generation to reject late results even if transport cancellation is ineffective. The host adapter reports 401 through its existing session invalidation path. In the composite viewer, load metadata then graph; render graph-provided metadata on success. Graph NOT_FOUND/UNAUTHENTICATED clears the whole composite, whereas graph FAILED/LIMIT_EXCEEDED retains separately authorized metadata with an unavailable graph. Standalone history/event errors clear their affected content without guessing whether the concealed cause was history denial or resource absence. The host owns coordination of session invalidation across mounted components.

The composite owns only metadata/graph reads; separate history/event components do not run until mounted, and the graph renderer never fetches. Optional navigation destinations are presentation choices, not permission discovery or new backend endpoints. Escape labels/evidence through normal text rendering and retain raw evidence text for downloads.

Sandbox provides reads using its existing transport and errors, navigation using its existing hash routes, session invalidation using existing logout handling, and messages/theme at the application boundary. Instance wrapper owns variables/effects and any host-only heading/navigation. History/event route wrappers pass route inputs to shared components. Keep exact evidence download/routing helpers in the library only where used by this slice; command-buffer behavior stays host-owned. Avoid retaining two copies of the same exact-value helper: if a helper is still needed by commands, expose a narrowly documented shared pure helper only after recording that necessity, or keep its host-specific behavior separate.

Build the UI package before its consumers. During T04, select and record one reproducible local built-package installation procedure for both sandbox and NgModule fixture, with committed lockfiles and no source path aliases. Do not maintain competing directory-link and tarball workflows. Exact tooling/commands are routine engineering choices, verified from a clean checkout before consumption is accepted.
