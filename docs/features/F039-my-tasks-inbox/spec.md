# F039 — My Tasks inbox

Revision 1 · IMPLEMENTED · 2026-11-24 · Owner: workflow maintainer. [Implementation and verification](implementation.md), [Constitution v6.6.1](../../constitution.md), [CON-03](../../constraints.md), [ASM-01](../../assumptions.md), [design sources](../../design-sources.md).

Reviewers should land on their newest open work, then be able to filter the same personal inbox and reopen a closed task. This revision covers the shared My Tasks list and its authorized read.

## Page behavior

- **R01 — Header and count.** Use the [F037 revision 2 task header](../F037-task-business-context-renderer/spec.md) with its workspace eyebrow, title typography, reviewer context and responsive alignment. Use the configured My Tasks title as the single H1 and restore “Your eligible open tasks, read from the workflow engine.” beneath it in both header layouts. Remove the duplicate “Assigned to you” introduction. Place **N on this page** at the upper right of the table toolbar on the same row as Refresh, including at narrow widths. N counts the visible rows on the current page, including zero on a successful empty page. Wrap the title as needed and clear stale counts with the rows.
  In the sandbox, render that H1 in the same white shell band as the individual task page and align the band with the table card. The sandbox owns the band and its breadcrumb. Host pages that supply their own header may hide the shared inbox header.
- **R02 — Filters.** Follow [F026 R07](../F026-task-administration-reassignment/spec.md#r07--task-administration-layout-revision-2). Show outlined Status (OPEN initially, COMPLETED, CANCELLED, ALL), Filters, Apply filters and Refresh above the table. The initially collapsed inline panel contains Task name, Task type code, Assignment kind, Assignment reference, Assignee reference and Instance ID in that order. Use F026's responsive grid, accessible toggle, explicit Apply and removable chips. Toggling preserves drafts without a request. Editing invalidates the old results. Chips describe the successful read. Removing a chip reapplies the remaining filters on page one. Removing Assignment kind also clears Assignment reference.
- **R03 — Filter matching.** Combine the criteria with AND inside the personal read. Use the Task Administration rules for case-insensitive literal substring matching of the pinned node name (maximum 200 UTF-16 units), exact identifiers and references, USER/GROUP/ROLE and the requirement for an assignment kind when filtering by assignment reference. Invalid criteria use the existing runtime validation feedback. A failed or superseded request must never present stale rows, counts or chips as current.
- **R04 — Created and ordering.** Append **Created** to the existing columns and format the task creation instant exactly as Task Administration does (Angular medium date and time in the same locale/time zone). Keep the task name as the link to the host-mapped task detail. Order all matching tasks by the full creation instant descending before pagination. For identical instants, use numeric task ID descending. Apply the same order to every status, including ALL across open and closed tasks. The formatted cell value, due date and closure time do not determine order.
- **R05 — Pagination.** Use the F026 R07 bottom navigation outside the table scroll region, with outlined Rows per page (20, 50, 100, default 50), live “Page N · X tasks on this page”, and Previous page / Next page with trailing chevron. Match its spacing, disabled states and narrow-width wrapping. Keep Refresh in the toolbar. Apply, chip removal, refresh and size changes return to page one. Previous re-fetches a visited cursor. Next follows the returned cursor even on an empty visible page. The footer count agrees with the upper-right count.
- **R06 — Personal visibility.** Every result requires the current actor's task-read permission. OPEN uses [F027 R03](../F027-runtime-read-policy-separation/spec.md) eligibility, including its current-assignee rule. ALL combines the open and closed personal sets without duplicates. The same rules apply to administrators visiting My Tasks. Opening a result uses the existing authorized task detail, including its read-only closed state.
- **R07 — Continuation.** For this personal inbox, R04 supersedes F027's ascending-ID list order. Preserve bounded examination (500 candidates, chunks of at most 100), the visible-row limit and response byte bound. Continue beyond examined filtered or denied candidates, and resume before a matching row withheld by the byte bound. On an unchanged dataset, paging forward reaches each match exactly once. Refresh starts at the newest currently visible match.

**Closed personal tasks (R06, owner decision).** Include a COMPLETED or CANCELLED task assigned to the actor at closure. Also include a COMPLETED task when the actor completed it, including an unclaimed shared task. Use the retained assignee or direct USER target for assignment at closure, including older USER rows with an empty assignee. Group or role membership alone, an earlier released claim, or having cancelled someone else's task does not qualify. Apply current host task-read permission in every case.

## Acceptance scenarios

1. **AC01 (R01, R04).** On desktop and a narrow screen, a reviewer sees one My Tasks title, the current count at the table toolbar's right edge on the Refresh row, and the Created column formatted like the same task in Task Administration. In the sandbox, the white title band and its alignment match the individual task page. A long title and a wide table leave the count and footer accessible. The task name opens the existing detail.
2. **AC02 (R02, R03, R06).** First load selects OPEN. Apply a status plus task name and an exact reference, then collapse the panel, remove a chip and try a reference without a kind. Results, chips, page number and validation follow the applied criteria. Changing to ALL includes only personal tasks the actor may currently read.
3. **AC03 (R04, R07).** Use creation times out of ID order, equal instants straddling a page boundary, and a recently closed older task. Across two or more pages, newest creation wins, ties follow descending ID, and no matching row repeats or disappears.
4. **AC04 (R01, R05, R07).** Follow Next through an empty page with continuation and return with Previous. The badge and footer show the same visible count. Previous is disabled on page one and Next at exhaustion. Refresh or change page size from a later page and observe the first page with its new count.
5. **AC05 (R06).** A reviewer finds an unclaimed shared task they completed under COMPLETED and a task assigned to them at cancellation under CANCELLED. ALL includes both alongside their eligible open work. A peer in the same group with neither personal relationship sees neither closed task. Revoked task-read permission excludes the row on the next read. Opening the completed result shows the existing read-only decision and any recorded comment.
