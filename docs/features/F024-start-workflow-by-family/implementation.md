# Implementation — F024 start workflow by family

## Delivered scope — revision 1, 2026-11-14

Implemented R01–R05 against F023 baseline `c147835`. Initial worktree contained the four untracked F024 planning documents and additive feature-index entry. Concurrent changes to docs/roadmap.md and later formatting of SandboxStart / the equivalent ConsoleRuntimeController wire-to-consoleWire rename appeared during implementation and were preserved. The rename/formatting do not change tested paths or behavior; the current forms were included in final source review.

Core accepts exactly one original selector, validates it for execution and lookup-only replay, resolves family starts after a receipt miss, and persists the concrete highest-numbered PUBLISHED pin. The bounded numeric query follows family write-lock acquisition/refresh; selected versions are refreshed with a write lock. F023 administration already uses family-before-version locking, so no administration or migration change was needed. Missing fresh targets map to NOT_FOUND, including exact drafts deleted before lock acquisition; absent retained pins remain HOST_CONFIGURATION. Known families without a publication return NO_PUBLISHED_VERSION. Pessimistic lock failures and SQL Server 1205/1222 map to CONCURRENT_COMMAND with their internal cause retained.

Exact-version Java constructors and fingerprint bytes remain compatible. Family requests use the distinct `wf-runtime-family-start-v1` fingerprint with the original key or family ID; receipt writes and both replay paths use that version. Replay returns the stored pin before resolution/capability/input-contract checks, with business correlation integrity checks retained. Result schemas, downstream pinned loading and completion are unchanged.

The sandbox parser accepts all selectors exclusively and rejects null, malformed, multiple and unknown fields for start/replay. SandboxStart passes the original selector through the existing transaction and lookup-only recovery path. Saved request data, administrator policy, CSRF configuration, link callback, atomic effects and durable handoff remain host-owned. README documents key-first integration. Shared web/UI and the explicit-version frontend envelope/form are unchanged.
