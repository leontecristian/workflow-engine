# Plan — F031

Implementation plan for the approved design in [revision 5](spec.md).

1. **Identity migration (R01a–R01c, R05).** Declare `WorkflowRequestIdentity` in `io.github.leontecristian.workflow.web.integration`. Wire it into the four explicit configurations. Migrate the viewer, runtime, definition and task-type controllers. Pass the captured actor through the viewer and graph services in `io.github.leontecristian.workflow.web.service.instance` to all five methods of `io.github.leontecristian.workflow.web.integration.instance.WorkflowViewerAccess`. Migrate the sandbox viewer adapter and its policy helpers to authorize that actor throughout. Declare `WorkflowUnauthenticatedException` in `io.github.leontecristian.workflow.web.exception` at the adapter boundary and map it through each group's scoped error handling. Capture the actor once while retaining authorization order and current-access rechecks. Consolidate sandbox actor lookup into one host bean and retain the existing policy, directory and audit adapters.
2. **Shared web (R01–R03).** Wire a concrete coordinator in `io.github.leontecristian.workflow.web.service.runtime` from `io.github.leontecristian.workflow.web.configuration`. Adapt the existing controller in `io.github.leontecristian.workflow.web.controller.runtime` and retire the forwarding contract in `io.github.leontecristian.workflow.web.integration.runtime`. Keep the endpoint coordinator outside the transaction. Use the host manager for a new transaction encompassing the core call and its commit. Observe its completion status and use a separate read-only transaction after a confirmed rollback. Keep this a controller entry point. A caller owning a business transaction continues to call core directly.
3. **Sandbox migration (R04–R05).** In `io.github.leontecristian.workflow.testhost.service.runtime`, retire shared-route forwarding and retain the host-owned start path. Preserve rollback and submission-visibility coverage at the transaction boundary in the shared HTTP integration fixture. Move direct command calls used by existing integration cases into a test-owned transaction fixture. Apply the existing sandbox post-result fault switch to host-owned starts, with the shared route fault exercised by the test fixture. The command controller currently handles all exceptions locally, so ordering a controller advice alone cannot guarantee the sandbox mapping. Use a sandbox-owned, narrowly scoped Spring MVC exception resolver ahead of controller exception handling, recognizing a sandbox conflict in the cause chain only for the shared command controller and preserving direct console error mapping. Reuse the sandbox error mapping in `io.github.leontecristian.workflow.testhost.service.console`, preserve the bounded runtime envelope, and delegate unrelated exceptions to the existing handlers. Document the Java migration in the web integration guide upon implementation.
4. **Administration audit (R06).** Make recorder injection optional in the administration configuration and change-recording branch of `io.github.leontecristian.workflow.web.service.administration`. The sandbox keeps its recorder. Update the integration guide and the activation test that currently requires the bean. Verify A07 with a recorder-free configuration and reuse applicable [F029 recorder and rollback evidence](../F029-administration-host-simplification/implementation.md) for the opted-in path, repeating affected checks where wiring changes invalidate it.
5. **Cancellation availability (R07).** Replace the context factory in `WorkflowRuntimeReadConfiguration` and `WorkflowRuntimeReadController` with an optional host `Clock`. Construct the operation context only after the R07 gates. Remove the factory interface and sandbox implementation. Document the hint migration in the web integration guide. Verify A08 through focused read configuration and controller tests, including clock capture and policy invocation order.
6. **Focused verification.** Exercise each activation mode and combined wiring, per-request actor resolution, scoped 401/500 responses and separate permissions (A04–A05). For A06, use focused viewer service and adapter tests to observe the actor at direct and default checks, concealed event denial, filtered summaries and graph link grants. Exercise activation, typed command/replay routing and A02 hit/miss/error branches using the affected web and sandbox unit suites. Use a guarded integration case to observe rollback followed by lookup in a different transaction and a shared-route HTTP case for wrapped sandbox conflict, checking the exact 409 and absence of automatic lookup. Retain the same-transaction submission-read check in the affected fixture. Use [F028 revision 3 evidence](../F028-completion-authorization-validation/implementation.md) for unchanged core authorization/receipt rules after checking applicability. It cannot establish the new transaction or HTTP boundary. Repeat the selected F029 audit rollback checks because the recorder activation path changed. Limit HTTP/SQL verification to the changed routes and wiring. Reuse browser evidence for unchanged UI interactions. Finish when A01–A08 pass and the migration instructions match the delivered dependencies.
