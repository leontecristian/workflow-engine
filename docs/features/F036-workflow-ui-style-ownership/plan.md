# F036 implementation plan

Revision 1 · [Requirements and acceptance](spec.md).

1. **Trace the cascade (R1).** Compare `workflow-test-host/frontend/src/styles.scss`, its media rules and sandbox templates with the root presentation primitives under `workflow-ui/projects/workflow-ui/src/lib/administration/support/` and the `administration/src/lib/` and `runtime/src/lib/` secondary entry points. For each moved or removed rule, identify its rendered owner, whether any sandbox-only templates still rely on it, and which layout, type or color is inherited. Record decisions in the implementation handover. A class-name match alone does not establish ownership.
2. **Move shared presentation (R1–R2).** Extend the actual component styles or existing shared Sass files. The identical layout rules in administration support and runtime are candidates for selective reuse. Share only demonstrated common treatments. Check Angular encapsulation at component and projection boundaries. For dialog content, inspect the rendered overlay before selecting the style owner. Keep selectors narrow and avoid publishing a second global Material theme. Inspect compiled styles for needless duplication.
3. **Fix Definitions (R3).** Update the page’s layout and badge in their owners. Exercise header action, count, footer, lookup, hint and import dialog. Update the Definitions lookup entry in the [style guide](../../frontend-style-guide.md) to match the delivered below-list placement. Retain historical F014 observations. Document the component/host ownership rule in [workflow-ui/README.md](../../../workflow-ui/README.md).
4. **Narrow sandbox globals (R4).** Remove duplicate workflow-specific declarations after their consumers have been accounted for. Scope any still-needed host rule to its sandbox owner. Preserve the existing shell and explicit host theme. Use the public presentation components already available where a sandbox page consumes them. Do not refactor unrelated templates.

## Verification plan

Concrete host consumers for the ownership check include [sandbox records](../../../workflow-test-host/frontend/src/app/ui/records.ts), [pagination](../../../workflow-test-host/frontend/src/app/ui/pagination.html) and [request forms](../../../workflow-test-host/frontend/src/app/pages/sandbox/requests.html). For example, the host still uses `.two-column`, which shares a responsive selector with workflow’s `.authoring-grid`. Split that selector before removing the workflow-specific dependency.

Use [the NgModule host](../../../workflow-ui/verification/ngmodule-host/src/main.ts) as an independent consumer of the **built package**, with its own [theme](../../../workflow-ui/verification/ngmodule-host/src/styles.scss) and controlled data. Keep verification fixture CSS free of substitutes for the selectors being verified. For A1–A3 capture a desktop and narrow Definitions state and inspect computed styles or bounding boxes where visuals are ambiguous. Confirm large/small counts, lookup position, representative shared runtime treatment, and an unaffected host control. Check touched dialog/overlay states in the browser. Exercise representative changed styles under a host theme without the sandbox’s custom variables; a precise copy of sandbox colors is not the goal.

Use the fixture's `styleOwnershipEvidence` modes `host`, `empty`, `populated`, `runtime` and `error` to compare host controls and overlays, empty and populated Definitions, affected runtime presentation, and read-error feedback. Serve the built sandbox frontend against controlled session and read fixtures for A4. Navigate from Requests to Task types and Instances in a single session to check that Angular applies each collection and pagination variant's own styles.

Use the sandbox build and a focused browser observation for A4. Reuse recorded [F014](../F014-definition-catalog-administration/implementation.md) pagination/dialog behavior and [F035](../F035-workflow-ui-http-adapter/implementation.md) installation/wiring evidence for unchanged contracts; neither proves the new CSS. No server, database, whole-workflow runs or APOLO checks are needed. Finish when the built-package and sandbox observations satisfy A1–A4.
