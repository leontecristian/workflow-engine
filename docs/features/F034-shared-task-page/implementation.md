# F034 — Implementation record

Implemented against READY revision 6. The owner-approved field allocation, fallback wording and named-field rules in [spec.md](spec.md) govern the delivered behavior.

## Implementation

- Shared web projects authorized business fields for exact task reads, My Tasks, instance task lists, activity submissions and previous decisions. Shared routes serialize the same safe projection for every actor. The sandbox uses the authenticated administrator role and exact task access on its own diagnostics route. Its raw retained history requires its administrator and instance grants. Reviewer business history has separate projections at the same browser destinations. Instance and graph authorization remain separate.
- Task mutations and receipt lookup use the task reference and the original opaque actor/task-bound precondition. Core still checks operation access, version and receipt identity. An actor with business access can recover their own receipt after the task itself is no longer visible. Responses report command state and authorized onward navigation. Validation responses expose business field locations and correction messages.
- The shared Task page places business context once before the decision, keeps completion on the task and presents accepted results as named values. The sandbox Task wrapper owns the final Technical details disclosure. Registered custom editors receive the pinned editor/outcome selections. Generic editors receive a projected description resolved from the pinned contract, with exact numeric data, named fields, repeated items, conditional dependencies and separate alternative drafts.
- The sandbox walkthrough uses the existing [amount review](../F018-structured-task-submissions/sandbox-structured-review.json). The [conditional items review](sandbox-conditional-items-review.json) is an independent importable example.

## F031/F032 boundary correction

- Restored `WorkflowAssignmentDirectory`, `WorkflowRuntimeOptions` and `WorkflowAuthorizedRuntimeReadService` to their HEAD signatures and behavior. Removed the proposed task diagnostics and submission authorization interfaces, optional lookups and sandbox implementations. The token codec is assembled inside shared web. Its optional stable key comes from the Spring environment as `workflow.runtime.task-token-key`.
- Exact submission reads retain the HEAD sequence of task access, evidence read and final completed-task authorization when the original view was open. Activity submission collections retain activity authorization and row-level exact-task checks. No extra submission grant or default allow was added.
- `WorkflowRequestIdentity` supplies an authenticated actor reference. `WorkflowRuntimeReadAuthorization` supplies resource visibility and completion advisory policy. Monitor and cross-instance task administration grant their particular views. `WorkflowAuthorization` gates runtime operations. `WorkflowAdministrationAuthorization` covers definition/catalog administration, and `WorkflowViewerAccess` grants retained evidence. None establishes a general administrator role in shared web. The approved sandbox-only endpoint uses existing `ConsoleContext.isConsoleAdministrator` and `ConsoleRuntimeAccess.task` before reading diagnostics.
- `WorkflowAssignmentDirectory.assignmentLabel(task)` can label the task target. The shared projection reuses this for a known USER owner or decision actor when the reference exactly matches an authorized task's USER target. For previous decisions the existing exact-task policy may independently grant the source task for attribution. A denied or unavailable source leaves the authorized decision visible with neutral attribution. The sandbox account store contains logins and roles. The existing identity and assignment APIs supply no arbitrary actor lookup. Claimants and prior actors without a matching permitted USER target use the approved fallbacks, with self and recorded system identities handled explicitly. A directory label equal to the raw reference is treated as unavailable.
- Independent review identified the raw pagination cursor, conditional alternative siblings, repeated form projection and definitive stale retry cases. The changes preserve opaque hidden-row continuation, retain branch limits and required fields, deduplicate shared safe descriptors and unlock the refreshed task after a definitive stale rejection with no receipt.
