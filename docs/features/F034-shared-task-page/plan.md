## Task HTTP migration

Task mutations use `POST /tasks/{taskId}/{operation}` with the original client UUID and operation fields. Lookup-only `POST /commands/{operation}/replay` adds the task reference to the body. Send the exact `X-Task-Precondition` from the contract response on both requests. The token protects the version of the same snapshot that supplies the task header and interaction permissions. Server-side authenticated encryption binds it to the trusted actor, task and purpose. The command coordinator resolves the task's instance and hands the original aggregate version to core. Core continues to own receipt identity, stale-write detection and permission checks. Previous decisions, My Tasks, instance tasks and Task administration use purpose-bound opaque cursors. A hidden row can advance the source scan without exposing its task reference.

Deploy the shared web endpoints, Angular contracts and host transports together. Complete or recover outstanding exports that use the prior instance-scoped task request before upgrading. Keep the token key stable across nodes and restarts where exported-request recovery is supported. Start and cancellation retain their existing instance-level transport.

Project task information and submissions after the existing exact-task and activity access checks. The shared task routes use the same safe projection for every caller. The owner approved the sandbox-owned `GET /console/api/tasks/{id}/diagnostics` route. It checks the authenticated administrator role and exact task access before reading or serializing evidence. Sandbox raw retained history requires the authenticated administrator role. Provide the authorized reviewer business projection for both history list and event detail using the sandbox instance and event policies. Instance viewing, commands, directory search and submission reads retain their existing grants.

The pinned form projection deduplicates repeated controls, rules and long text values using response-local identities. The sandbox transport resolves those references before handing the form to the editor. The form never carries the authored schema or its local reference paths.

Use the original `WorkflowAssignmentDirectory.assignmentLabel(task)` for authorized targets. It can identify a person only when a known subject matches the USER assignment. A previous decision may use the source task's assignment label when the existing exact-task policy independently allows reading that source. Receiving-task access continues to govern the decision itself. Compare the trusted actor reference for self-attribution and use the approved fallbacks when an assignment cannot identify the person. An independent display-name query for arbitrary actors has no existing adapter. The sandbox uses the existing [amount review](../F018-structured-task-submissions/sandbox-structured-review.json) and a separate [repeating conditional review](sandbox-conditional-items-review.json).
